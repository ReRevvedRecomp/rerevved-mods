# Automated and AI-assisted contributions

If automated or AI assistance is used, the work follows the same contribution and evidence rules as any other work.
The contributor owns every submitted claim and must be able to explain its source, scope, and supporting evidence.

Automated output is not guest code or runtime evidence. Gameplay claims require
the applicable ReRevved analysis and runtime evidence. Build and package success
alone does not establish runtime behavior. This repository consumes the settled
public title API. It does not recover or duplicate guest addresses, layouts, or
state machines.

## Public contribution policy

- Follow the repository boundaries and dependency requirements in
  [CONTRIBUTING.md](../../CONTRIBUTING.md).
- Keep tracked documentation current and public. Do not include credentials,
  machine paths, retail files, extracted assets, or generated output.
- Apply this boundary to all tracked Markdown and structured data. Do not include
  prompts, assignments, handoffs, work-session plans, self-review metadata,
  private paths, or internal milestone identifiers. Structured records retain
  evidence and current conclusions. Tests assert semantic contracts.
- Put each settled fact in one canonical guide and link to it elsewhere.
- Preserve addresses, offsets, hashes, tool names, uncertainty, and provenance
  citations when they support a claim.
